# Воздушный праздник — интернет-магазин (v8)

Сайт магазина пиротехники и гелиевых шаров в Челябинске. Это локальная MVP-версия, не прошедшая полноценное production-тестирование.

## Установка

Требуется Node.js 22+. В папке проекта выполнить `npm ci`, затем `npm run setup` и `npm start`. Команда setup создаёт `.env` со случайными секретами и не перезаписывает существующий файл. Пароль администратора — значение `ADMIN_PASSWORD` в вашем `.env`. Сайт: http://127.0.0.1:3000, панель управления: http://127.0.0.1:3000/admin.html.

При обновлении со старой версии перенести **свой** `.env` и `private/store.json`, предварительно создав их резервные копии. Никогда не публиковать `.env` или `private/store.json`.

## Настройки окружения

- `HOST` — по умолчанию `127.0.0.1`: доступ только с вашего компьютера. Для доступа по локальной сети задайте `0.0.0.0` осознанно.
- `DATA_DIR` — необязательный отдельный каталог данных, например для тестирования.
- `TRUST_PROXY` — список доверенных адресов/подсетей прокси через запятую. Оставьте пустым при прямом локальном запуске.
- `PORT` — порт сервера, по умолчанию 3000.
- `NODE_ENV` — `development` для локальной работы, `production` для размещения.
- `SESSION_SECRET` — случайная строка длиной не менее 32 символов. Изменение завершает ранее выданные сессии.
- `ADMIN_PASSWORD` — пароль администратора, минимум 12 символов.
- `RESEND_API_KEY` и `MAIL_FROM` — отправка писем через HTTPS API Resend. Для произвольных адресатов требуется подтверждённый домен отправителя.
- `YANDEX_MAPS_API_KEY` — JavaScript API Яндекс Карт для выбора адреса доставки; не используется для отзывов.

В development без настроенной почты коды регистрации и восстановления выводятся **в терминал сервера**. В production без почтового сервиса отправка кодов недоступна.

## Возможности сайта

- Главная страница с категориями, товарами, преимуществами, магазинами, блоком избранных отзывов и формой связи.
- Каталог с поиском и карточками товаров, отдельный раздел гелиевых шаров.
- Корзина, оформление заказа с оплатой при получении; самовывоз из пяти магазинов либо доставка по Челябинску с выбором точки на карте.
- Регистрация с обязательными именем, телефоном, email и паролем; подтверждение шестизначным кодом из письма.
- Вход по email и паролю, сессии пользователя и администратора разделены.
- Восстановление пароля: запрос кода на email, ввод кода и нового пароля дважды. Код одноразовый, действителен 5 минут, до 5 попыток. После сброса старые пользовательские сессии отзываются.
- Профиль с редактированием данных и историей заказов, статусы заказов на русском языке.
- Оптовая заявка, обратная связь для авторизованных клиентов.
- Админ-панель: товары, заказы, клиенты, заявки, создание и модерация отзывов. Отзывы публикуются только через админку, виджета Яндекс Отзывов нет.
- Единая светлая тема и SVG-иконки; тёмная тема полностью удалена.

## Данные и безопасность

Данные сохраняются в `private/store.json`. Пароли клиентов хешируются `scrypt` с индивидуальной солью, токены сессий сохраняются только в виде хешей. Используются HttpOnly cookie, проверка Origin для запросов изменения, Helmet и ограничения частоты запросов. Для публичного запуска необходимы PostgreSQL, резервное копирование, полноценная серверная геопроверка зоны доставки, тестирование и проверка правовых ограничений продажи/доставки пиротехники.

## Известные ограничения

- MiDays пока не подключён: версия и документация API неизвестны.
- Проверка адреса доставки на сервере пока недостаточно надёжна для коммерческого запуска.
- Отзывы из Яндекс Карт и 2ГИС автоматически не импортируются; отзывы создаёт и публикует администратор.
- Отправка email зависит от настройки Resend и домена отправителя.
- Локальное JSON-хранилище не подходит для нескольких одновременно работающих серверов.

## Проверка

Запустить `npm run check` и `npm test`. Интеграционные тесты используют временное хранилище, проверяют неверный ввод, защиту маршрутов, регистрацию, восстановление пароля, отзыв сессий, остатки и отмену заказов. Затем проверить интерфейс в браузере. Не использовать реальные секреты в тестовых отчётах.


## Хранение и восстановление

`private/store.json` исключён из отслеживания Git; ваша локальная копия сохраняется. Файл уже присутствовал в старых коммитах: удаление из текущего дерева не удаляет историю. Если там были реальные данные, ограничьте доступ к репозиторию и отдельно очистите историю после резервного копирования; смените затронутые пароли.

Сервер допускает только один процесс на каталог данных (`server.lock`). После аварийного завершения устаревшая блокировка снимается при следующем запуске, если процесса уже нет. Не удаляйте блокировку работающего сервера.

Перед сохранением создаётся `store.json.bak` — предыдущая версия базы. Это не замена независимым резервным копиям. Для восстановления остановите сервер, сохраните текущий повреждённый файл отдельно и скопируйте проверенную резервную копию в `store.json`. Не открывайте доступ к каталогу `private` через веб-сервер.

Новые заказы резервируют остатки. Отмена возвращает резерв ровно один раз; завершённые и отменённые заказы нельзя открыть повторно. Старые заказы без признака резерва не меняют остатки при отмене. Повторяющиеся строки товара отклоняются. Доставка остаётся заявкой, адрес и возможность передачи проверяет менеджер; автоматическая сверка адреса с картой не реализована.

Админ-сессия действует 8 часов и отзывается при смене `ADMIN_PASSWORD`; пользовательская — 7 дней, до пяти сессий. Ограничения входа по аккаунту сохраняются в базе на 15 минут. После обновления старые админ-сессии потребуют повторного входа.


## Проверка интерфейса

`npm run test:browser` проверяет страницы при ширине 390 и 1440 пикселей, регистрацию, вход, создание товара и оформление заказа в отдельной временной базе. Для браузерных проверок нужен Chromium: `npx playwright install chromium` (в Linux могут дополнительно потребоваться системные библиотеки). Можно указать установленный браузер через `CHROMIUM_PATH`. Обычные `npm test` не требуют браузера. Тесты не обращаются к рабочей базе и внешнему почтовому сервису.
